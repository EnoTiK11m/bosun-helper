# Bosun Helper

Расширение для Chrome и Chromium, которое ускоряет работу с алертами Bosun и помогает безопасно переходить к запросам в Grafana.

Bosun Helper уменьшает визуальный шум на дашборде, выделяет важные алерты
и добавляет быстрые действия для дежурного. Фильтры, уведомления, Priority
и шаблоны комментариев настраиваются прямо на странице Bosun.
Расширение устанавливается из исходников как распакованное расширение Chrome/Chromium.

Для Grafana действует принцип fail closed: если запрос или соответствие алерта
нельзя подтвердить, расширение не предлагает действие. Ack, Note и Close
автоматически не выполняются — отправка остаётся за пользователем.

## Что умеет

### Работа с алертами

- Показывает возраст вместо `1 alerts` у однозначно сопоставленной одиночной
  группы в Needs Acknowledgement и Acknowledged.
- Обозначает алерты с Note, позволяет копировать Subject, всю группу
  и текст последней заметки.
- Скрывает Silenced, фильтрует Needs Ack без пользовательского комментария
  и сворачивает Acknowledged.
- Улучшает checkbox и размещение элементов в строке; делает ссылки
  в Last Action удобнее для открытия и копирования.
- Показывает уведомления о новых Needs Ack и воспроизводит звуковой сигнал.
- Обновляет страницу после бездействия, учитывая редактирование,
  выделение текста и видимость вкладки.

### Priority Alerts

- Выделяет приоритетные алерты флагом `⚑` и подсветкой, сохраняя их статус.
- Поддерживает точные имена алертов и автоматический Priority для Critical.
- Позволяет добавить или удалить правило по точному имени внутри конкретного
  алерта в раскрытой группе.
- Даёт отдельно настроить показ Priority в Acknowledged и видимость
  кнопки управления правилом.

### Быстрые комментарии и Grafana

- Хранит отдельные шаблоны Note, Ack и Close; кнопка вставляет текст в форму.
- Показывает предпросмотр PromQL перед переходом в настроенную панель Grafana.
- Предлагает режимы **Вставить** и **Вставить и выполнить**.

## Быстрый старт

1. Клонируйте репозиторий или скачайте и распакуйте его архив.
2. Откройте терминал в корне проекта и создайте локальную конфигурацию
   из [config.example.js](config.example.js):

   ```powershell
   Copy-Item config.example.js config.local.js
   ```

   В Bash используйте `cp config.example.js config.local.js`.

3. В `config.local.js` укажите адреса Bosun, host Grafana и URL панели
   редактирования. Пример приведён в разделе [Настройка](#настройка).
4. Синхронизируйте конфигурацию:

   ```bash
   npm run sync-config
   ```

5. Откройте `chrome://extensions` и включите **Режим разработчика**.
6. Нажмите **Загрузить распакованное расширение** / **Load unpacked**.
7. Выберите корень проекта — директорию с `manifest.json`.
8. Перезагрузите открытые страницы Bosun и Grafana.

В Edge используйте страницу `edge://extensions` и тот же порядок загрузки.

## Требования

- Chrome, Chromium или Microsoft Edge с поддержкой Manifest V3.
- Доступ к настроенным HTTPS-адресам Bosun и Grafana.
- Node.js **20 или новее** для настройки и разработки.
  Для проверок в браузере рекомендуется **Node.js 22+**; требуется глобальный
  `WebSocket` и установленный Chrome, Chromium или Edge.

Расширение работает без сборки и не требует npm-зависимостей для своей работы.
Для приведённых команд не требуется `npm install`.

## Настройка

Пример `config.local.js` с публично безопасными адресами:

```js
globalThis.BosunHelperLocalConfig = {
  bosunHosts: ['bosun.example.com', 'bosun-test.example.com'],
  grafanaHost: 'grafana.example.com',
  grafanaPanelUrl: 'https://grafana.example.com/d/example/dashboard?orgId=1&editPanel=1'
};
```

| Поле | Что указать |
| --- | --- |
| `bosunHosts` | Имена серверов Bosun без протокола и пути; можно указать несколько. |
| `grafanaHost` | Имя сервера Grafana без протокола и пути. |
| `grafanaPanelUrl` | HTTPS-URL нужной панели в режиме редактирования с `editPanel`. |

Имя сервера в `grafanaPanelUrl` должно совпадать с `grafanaHost`.
При необходимости оно может включать порт.

После изменения адресов выполните `npm run sync-config`, обновите расширение
на странице управления расширениями и перезагрузите вкладки.
Команда обновляет `config.js` и разрешённые адреса в `manifest.json`.

`config.local.js` игнорируется Git. Не публикуйте его и внутренние адреса.
Перед публичным commit выполните:

```bash
npm run prepare-commit
```

Проверьте diff: для публикации должны использоваться безопасные example-адреса.
Команда сама не выполняет staging или commit. После commit восстановите
локальную конфигурацию:

```bash
npm run sync-config
```

## Использование

### Bosun

1. Откройте главный дашборд Bosun.
2. В верхней панели используйте фильтры, звук и **⚙ Настройки**.
3. Раскройте группу и нужный алерт.
4. Используйте **Копировать**, **Grafana** или кнопку Priority,
   когда соответствующее действие доступно.

У одиночной группы вместо счётчика может отображаться возраст алерта.
При неоднозначных данных сохраняется штатный счётчик Bosun.
Группы из нескольких алертов продолжают показывать количество.

Обычные действия Note, Ack и Close выполняются через форму Bosun.
Шаблоны и кнопки расширения помогают подготовить данные для работы.

### Priority Alerts

Priority — дополнительное выделение важности. Флаг и подсветка не меняют
статус Critical, Warning или Unknown.

В разделе **Priority Alerts** настроек:

- включите Priority Alerts — по умолчанию функция выключена;
- добавьте точные имена алертов, по одному на строку;
- при необходимости отключите автоматический Priority для Critical;
- включите показ Priority в Acknowledged, если он нужен.

Точные имена учитывают регистр и не являются шаблонами или regexp.
Настройка автоматического Priority для Critical включена по умолчанию,
но действует только при включённой функции Priority Alerts.
Показ Priority в Acknowledged по умолчанию выключен.

Внутри конкретного алерта в раскрытой группе доступны:

- **⚑ В приоритетные** — добавить правило для точного имени этого алерта;
- **⚑ Убрать из приоритетных** — удалить это правило.

На внешней строке группы управляющей кнопки нет.
При этом группа может сохранять флаг Priority и подсветку.
Если алерт остаётся Priority из-за Critical, удаление правила
не снимает его приоритетное выделение.

Настройка **Кнопка управления приоритетом в алерте** включена по умолчанию.
Её можно выключить без перезагрузки: исчезнут только быстрые кнопки.
Сохранённые правила и приоритетное выделение останутся; редактор правил
в настройках будет доступен. Кнопкой можно пользоваться и в Acknowledged,
даже когда показ Priority в этой секции выключен.

### Частые комментарии

1. Откройте форму Note, Ack или Close в Bosun.
2. Нажмите подходящий шаблон в блоке **Частые комментарии**.
3. При необходимости дополните текст и отправьте форму самостоятельно.

Кнопка **⚙** рядом с заголовком открывает редактор шаблонов текущего типа.
Можно добавлять, менять, удалять и переставлять записи, а также возвращать
встроенные значения. Note, Ack и Close настраиваются независимо.

### Grafana

1. Нажмите **Grafana** у алерта.
2. Проверьте полный запрос в предпросмотре PromQL.
3. Выберите действие:

   - **Отмена** — закрыть предпросмотр;
   - **Вставить** — открыть панель и перенести запрос без Run;
   - **Вставить и выполнить** — перенести запрос и выполнить его после проверки редактора.

Расширение использует настроенную панель Grafana.
Перед выполнением проверьте запрос, источник данных и временной диапазон.
Если корректный запрос или соответствие алерта не подтверждены,
кнопка Grafana не предоставляется.

## Настройки

**⚙ Настройки** на дашборде объединяет:

- интерфейс, возраст, копирование, checkbox и Last Action;
- фильтры и визуальные уведомления;
- правила Priority и отображение Priority;
- звук и автообновление;
- шаблоны Note/Ack/Close;
- включение интеграции с Grafana.

Настройки сохраняются локально и синхронизируются между вкладками расширения.
Большинство изменений применяется сразу. Изменение улучшений Last Action
требует перезагрузки страницы; это указано рядом с настройкой.

Несохранённый текст в редакторе правил или шаблонов сохраняется при перерисовке
и внешнем обновлении настроек. Явный сброс возвращает значения настроек.
Общий сброс не очищает рабочие записи уведомлений и ожидающих переносов в Grafana.

## Безопасность и приватность

- Ack, Note и Close не выполняются автоматически.
- Неоднозначное или конфликтующее сопоставление даёт безопасный отказ.
- При неподдерживаемом или некорректном PromQL кнопка Grafana отсутствует.
- Run возможен только после явного выбора пользователя и проверки актуальных
  целевой панели, редактора и вставленного запроса.
- Расширение не добавляет внешнюю телеметрию.
- Полные снимки `/api/alerts` не сохраняются в хранилище браузера.
- Конфигурация ограничивает разрешённые адреса Bosun и Grafana.
- Пользовательские настройки и шаблоны хранятся локально в браузере.

## Ограничения Grafana integration

Bosun Helper предпочитает не показать действие, если не может доказать
корректность переноса запроса.

Поддерживаются распространённые `promras`, цепочки переменных и безопасные
формы арифметики. Для устаревшего `prom` и `merge(addtags(...), addtags(...))`
поддержка ограничена узкими проверяемыми формами.
Общей поддержки произвольных выражений Bosun нет: `dropna`, `promrate`,
имена метрик с точками в устаревшем `prom` и другие неподдерживаемые формы отклоняются.

Перенос PromQL не воспроизводит полный набор данных Bosun. Шаг и диапазон Bosun
не переносятся автоматически в Grafana; результат зависит от настроек панели.
Перенос нескольких отдельных запросов одним действием не поддерживается.
Если редактор нельзя безопасно определить или панель изменилась,
вставка или Run отменяются.

## Разработка

Исходники написаны на JavaScript; отдельного этапа сборки нет.
Перед PR выполните:

```bash
npm test
npm run test:browser
npm run check
git diff --check
```

| Команда | Назначение |
| --- | --- |
| `npm test` | Проверки логики, настроек, интеграции и регрессий в Node.js. |
| `npm run test:browser` | Проверки DOM и пользовательских сценариев в Chromium-браузере. |
| `npm run check` | Проверка JavaScript, manifest и основных наборов тестов. |
| `git diff --check` | Проверка пробельных ошибок в изменениях. |
| `npm run sync-config` | Применение локальных адресов. |
| `npm run prepare-commit` | Подготовка публично безопасной конфигурации. |

Структура проекта:

```text
src/bosun/     — интерфейс и работа с алертами
src/grafana/   — запросы, предпросмотр и перенос в Grafana
src/settings/  — настройки и их интерфейс
src/shared/    — общие механизмы
tests/         — автоматические проверки
scripts/       — конфигурация и проверки проекта
```

Для тестовых примеров используйте только синтетические данные.
Не включайте в PR внутренние адреса, URL, реальные алерты, токены
или клиентские данные.

## Если что-то не работает

| Ситуация | Что проверить |
| --- | --- |
| Интерфейс расширения не появился | Расширение включено; адрес Bosun указан в конфигурации; `sync-config` выполнен. Обновите расширение и страницу. |
| Нет кнопки Grafana | Проверьте, что интеграция включена. Кнопка появляется только для поддерживаемого запроса и однозначно сопоставленного алерта; её отсутствие может быть ожидаемым безопасным отказом. |
| Grafana не открывается | Проверьте `grafanaHost` / `grafanaPanelUrl`, доступ к панели и разрешение браузера на открытие новой вкладки. |
| Запрос не вставился или Run не выполнен | Убедитесь, что открыта настроенная панель редактирования Grafana. Если редактор нельзя определить однозначно, расширение отменяет вставку. Проверьте содержимое редактора; при необходимости продолжите вручную. |
| Тесты в браузере не находят Chrome | Установите Chrome, Chromium или Edge либо задайте `BOSUN_HELPER_BROWSER` — путь к исполняемому файлу или имя команды. Для запуска используйте Node.js с глобальным `WebSocket`. |

Если звука нет, сначала кликните на странице или нажмите клавишу:
браузер может блокировать звук до первого взаимодействия.
Затем проверьте настройку звука и убедитесь, что вкладка не заглушена.
